## Introduction

DeepSeek-V4-Flash is a Mixture-of-Experts (MoE) large language model developed by DeepSeek, featuring 284B total
parameters with 13B active parameters. It employs hybrid sparse attention (CSA + HCA) and DeepSeekMoE architecture with
a bundled multi-token prediction (MTP) draft head for speculative decoding, supporting a 1M-token context length.

This document demonstrates the deployment of DeepSeek-V4-Flash on Ascend NPUs using SGLang on the **A3 Series** and the
**950PR/DT Series** (A5 SoC). It covers single-node PD mixed deployment, feature configuration, and performance
optimization. The multi-node PD disaggregation commands for both platforms are documented in the
[Best Practice](#best-practices) page.

This document is validated and written based on **SGLang v0.5.23**. The current model (DeepSeek-V4-Flash) is fully
supported in this version. To use the latest features (e.g., PD disaggregation, DSpark speculative decoding), it is
recommended to use v0.5.23 or a later version.

<Note>
The 950PR/DT Series examples rely on DeepSeek-V4 DSpark speculative decoding and prefill context parallelism support on
the 950PR/DT Series. Run them on a daily build newer than v0.5.23, for example `cann9.1.0-950-B105`.
</Note>

## Supported features

| Feature                       | Example usage                                                                                 |
|-------------------------------|-----------------------------------------------------------------------------------------------|
| Attention Backend             | A3 Series: `--attention-backend dsv4`<br/>950PR/DT Series: `--attention-backend ascend`       |
| Tensor Parallelism            | A3 Series: `--tp-size 16` (8 cards)<br/>950PR/DT Series: `--tp-size 8`                        |
| Data Parallelism              | A3 Series: `--dp-size 16`<br/>950PR/DT Series: `--dp-size 8`                                  |
| Expert Parallelism            | A3 Series: `--ep-size 16`<br/>950PR/DT Series: `--ep-size 8`<br/>`--moe-a2a-backend deepep \`<br/>`--deepep-mode auto`                    |
| PD Disaggregation             | `--disaggregation-mode prefill \`<br/>`--disaggregation-transfer-backend ascend`              |
| Quantization                  | A3 Series: `--quantization modelslim` (W8A8 INT8)<br/>950PR/DT Series: `--quantization fp8`   |
| KV Cache Dtype                | `--kv-cache-dtype auto` (resolves to bfloat16 on NPU)                                         |
| NPU Graph                     | enabled by default; disable with `--disable-cuda-graph`;<br/>control range via `--cuda-graph-bs-decode` or `--cuda-graph-max-bs-decode`; e.g., `--cuda-graph-bs-decode 1 2 4 8 16 24 36 40 48 56` |
| Speculative Decoding          | `--speculative-algorithm DSPARK \`<br/>`--speculative-num-draft-tokens 7 \`<br/>`--speculative-dspark-block-size 6` |
| Prefill Context Parallel      | `--enable-prefill-cp \`<br/>`--cp-strategy interleave`                                        |
| Overlap Schedule              | `export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1`                                                  |
| DP LM Head                    | `--enable-dp-lm-head`                                                                         |
| DP Attention                  | `--dp-size 16 \`<br/>`--enable-dp-attention`                                                                           |

<Note>
The values in the **Example usage** column are for illustration only. Adjust them according to your hardware, deployment
mode, and workload. For parameter details, see
[Feature descriptions](/docs/hardware-platforms/ascend-npus/optimization/parameter_tuning#feature-descriptions); for
recommended configurations for each deployment scenario, see [Best practices](#best-practices).
</Note>

<Note>
`--dp-size <n> --enable-dp-attention` and `--disable-cuda-graph` are still accepted, but the current spellings are
`--attn-dp-size <n>` and `--cuda-graph-backend-prefill=disabled`. The examples on this page keep the spellings used by
the validated launch scripts.
</Note>

For feature compatibility and conflict information between features,
see [Feature Compatibility](/docs/hardware-platforms/ascend-npus/optimization/parameter_tuning#feature-compatibility).

## Prerequisites

### Environment

Before following this tutorial, complete the environment setup in the documents below:

- [Ascend NPU Quickstart](/docs/hardware-platforms/ascend-npus/getting-started/quick_start) — the fastest way to get started.
  It walks you through launching the official container image, starting the SGLang server, and sending a test request.
  Recommended if you are new to SGLang on Ascend.
- [SGLang Installation with NPU Support](/docs/hardware-platforms/ascend-npus/getting-started/installation) — the full installation guide.
  It covers the component version mapping (CANN, TorchNPU, Triton, kernels, etc.), building from source or from a
  Dockerfile, and recommended system settings (CPU power scheme, NUMA, swap). Use it when you need to install or customize
  the environment instead of using the official image.

For the 950PR/DT Series, also install the `950` release of the SGLang NPU kernels and set `ASCEND_USE_FIA=1`, as
described in the installation guide.

### Model weights

Before downloading model weights, check the model size to reserve enough disk space.
For multi-node deployment, download the weights to a shared directory accessible to all nodes.

- [deepseek-ai/DeepSeek-V4-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash) — official checkpoint (block FP8),
  used by the 950PR/DT Series examples.
- [DeepSeek-V4-Flash-w8a8-mtp](https://www.modelscope.cn/models/Eco-Tech/DeepSeek-V4-Flash-w8a8-mtp) — W8A8 INT8 quantized
  version (300GB), used by the A3 Series examples.

<Info>
The W8A8 variant (300GB) can be deployed on 8 × 64GB of device memory (`--tp-size 8`), which corresponds to 8 dies on an
A3 Series node (4 cards). The examples below use a full A3 Series node (16 dies, `--tp-size 16`) and a single 950PR/DT
Series node (8 devices, `--tp-size 8`).
</Info>

This is the minimum recommended configuration. For optimized configurations,
see [Best practices](#best-practices), which may require additional cards or nodes.

For the hardware specifications (memory per die and dies per card),
see [Ascend NPU Reference — Hardware](/docs/hardware-platforms/ascend-npus/reference/glossary#hardware).

## Installation

<Warning>
Ensure sufficient disk space before pulling images. The Docker image requires at least **30GB** of free space.
</Warning>

The dependencies required for the NPU runtime environment have been integrated into a Docker image and uploaded to the
online platform. You can directly pull it.

Both **stable releases** and **daily builds** are available. CANN 9.1.0 has no stable release yet, so the following
commands use the validated build tag of each platform.
For details, see [Docker image versions](/docs/hardware-platforms/ascend-npus/faq#8-docker-image-versions-stable-release-vs-daily-build).

## Online service deployment

### Single-node PD mixed deployment

Single-node deployment completes both prefill and decode within the same node (PD mixed mode), which keeps the
deployment simple and avoids dedicating a second node to prefill. Select the tab for your platform and run the script
inside the container.

<Tabs>
  <Tab title="A3 Series">

Use the W8A8 checkpoint on one full A3 Series node: 8 cards, 16 dies, `--tp-size 16`. DSpark speculative decoding runs
against the bundled draft head of the same checkpoint.

```bash Command
# ============================================================
# Before running, update the following variables:
#   MODEL_PATH: path to the model weights directory
# ============================================================

MODEL_PATH=/path/to/model-weights

echo performance | tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
sysctl -w vm.swappiness=0
sysctl -w kernel.numa_balancing=0
sysctl -w kernel.sched_migration_cost_ns=50000

unset https_proxy http_proxy HTTPS_PROXY HTTP_PROXY ASCEND_LAUNCH_BLOCKING

source /usr/local/Ascend/ascend-toolkit/set_env.sh
source /usr/local/Ascend/nnal/atb/set_env.sh
source /usr/local/Ascend/ascend-toolkit/latest/opp/vendors/customize/bin/set_env.bash
source /usr/local/Ascend/ascend-toolkit/latest/opp/vendors/custom_transformer/bin/set_env.bash

export DEEPEP_HCCL_BUFFSIZE=2500
export DEEP_NORMAL_MODE_USE_INT8_QUANT=1
export FORCE_DRAFT_MODEL_NON_QUANT=1
export GLOO_SOCKET_IFNAME=lo
export HCCL_OP_EXPANSION_MODE=AIV
export HCCL_SOCKET_IFNAME=lo
export INF_NAN_MODE_FORCE_DISABLE=1
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
export SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK=96
export SGLANG_DSPARK_FAST_KERNEL=0
export SGLANG_DSV4_FP4_EXPERTS=False
export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1
export SGLANG_ENABLE_SPEC_V2=1
export SGLANG_ENABLE_TP_MEMORY_INBALANCE_CHECK=0
export SGLANG_ENABLE_WAR_BARRIER=1
export SGLANG_FORCE_COARSE_WAR_BARRIER=1
export SGLANG_OPT_BF16_FP32_GEMM_ALGO=torch
export SGLANG_OPT_DEEPGEMM_HC_PRENORM=False
export SGLANG_OPT_FP8_WO_A_GEMM=0
export SGLANG_OPT_FUSE_WQA_WKV=0
export SGLANG_OPT_USE_FUSED_HASH_TOPK=False
export SGLANG_OPT_USE_OVERLAP_STORE_CACHE=False
export SGLANG_OPT_USE_TILELANG_MHC_POST=False
export SGLANG_OPT_USE_TILELANG_MHC_PRE=False
export SGLANG_RAGGED_VERIFY_MODE=static
export SGLANG_SET_CPU_AFFINITY=1
export SGLANG_ZBAL_BOOTSTRAP_URL=tcp://127.0.0.1:14699
export SGLANG_ZBAL_LOCAL_MEM_SIZE=61000
export STREAMS_PER_DEVICE=32
export ZBAL_ENABLE_GRAPH=1
export ZBAL_NPU_ALLOC_CONF=use_vmm_for_static_memory:True

python3 -m sglang.launch_server \
    --model-path "$MODEL_PATH" \
    --host 127.0.0.1 --port 6688 \
    --page-size 128 \
    --tp-size 16 \
    --trust-remote-code \
    --device npu \
    --attention-backend dsv4 \
    --watchdog-timeout 9000 \
    --mem-fraction-static 0.68 \
    --prefill-max-requests 192 \
    --max-prefill-tokens 80000 \
    --chunked-prefill-size 131072 \
    --max-running-requests 192 \
    --dp-size 16 \
    --enable-dp-attention \
    --moe-a2a-backend deepep \
    --deepep-mode auto \
    --quantization modelslim \
    --enable-dp-lm-head \
    --kv-cache-dtype auto \
    --load-balance-method round_robin \
    --cuda-graph-bs-decode 1 2 4 6 8 10 \
    --speculative-algorithm DSPARK \
    --speculative-draft-model-path "$MODEL_PATH" \
    --speculative-draft-model-quantization modelslim \
    --speculative-draft-attention-backend ascend \
    --speculative-num-draft-tokens 7 \
    --speculative-dspark-block-size 6 \
    --disable-radix-cache
```

  </Tab>

## Functional verification

After the service is started, you can invoke the model by sending a prompt:

```shell
# ============================================================
# Before running, update the following variables:
#   HOST: the server host address (e.g., localhost)
#   PORT: the server port number (e.g., 6688)
# ============================================================

curl http://${HOST}:${PORT}/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
        "model": "deepseek-v4-flash",
        "messages": [{"role": "user", "content": "What is the capital of France?"}]
    }'
```

Expected result: an HTTP 200 response with the generated text containing "Paris".

Once the server prints `The server is fired up and ready to roll!` in the logs, it is ready to accept requests. The
single-node examples on this page serve on port `6688`; for PD disaggregation, send client requests to the router on
port `6688` as well, while the prefill and decode workers listen on ports `8000` and `8001`. For more testing examples
(Health Check, Generate, Chat Completions, and port usage guidance),
see [Testing the Service](/docs/hardware-platforms/ascend-npus/getting-started/installation#testing-the-service).
